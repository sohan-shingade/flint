**Goal**: A quant firm finds Flint on GitHub → clones → running backtests with their own strategies within hours

## Critical Gaps Found (Blockers for Professional Use)

The brainstorm audit found 7 blocking issues:

1. **No CLI** — zero command-line interface. No `flint backtest`, no `flint init`. Only way to interact is booting FastAPI or writing custom scripts. Every competitor has a CLI.
2. **No quickstart automation** — no `Makefile`, no `docker-compose.yml`, no `flint init`. Manual wiring required.
3. **Live trading is a dead end** — `DriftConnector.place_order()` raises `NotImplementedError`. No wallet integration, no `driftpy` dependency.
4. **No multi-market backtesting** — `BacktestEngine.run()` takes one market's candles. Cross-market strategies (pairs, funding arb) are impossible.
5. **No statistical confidence** — no Monte Carlo, no confidence intervals on Sharpe. Single point-estimate metrics. No quant firm will allocate capital on this.
6. **No data validation** — candle data is ingested and trusted blindly. Gaps, staleness, anomalies are silent.
7. **Strategy testing requires API server** — can't run a backtest from CLI against a local `.py` file.

## Feature List (Prioritized)

### Tier 1 — Must Build (blocks professional adoption)

#### 1. `flint` CLI with init/backtest/optimize/serve

**What**: `typer`-based CLI with `console_scripts` entry point. Commands:
- `flint init` — scaffold project, create config, backfill 90 days of SOL-PERP data
- `flint backtest strategies/my_strat.py --market SOL-PERP --period 90d` — run from terminal, rich table output
- `flint optimize strategies/my_strat.py --metric sharpe --trials 100`
- `flint paper strategies/my_strat.py --market SOL-PERP`
- `flint serve` — start API + UI
- `flint data download --market SOL-PERP --days 365`
- `flint data status` — show data coverage

**Why #1**: Every competitor has a CLI (Freqtrade: 20+ commands, Jesse: `jesse backtest`, QuantConnect: `lean backtest`). Without this, no professional gets past the first 30 minutes. This is the single highest-friction item.

**Effort**: Medium (1-2 sessions)

---

#### 2. Multi-Market Backtest Engine

**What**: Extend `BacktestEngine.run()` to accept `Dict[str, List[Candle]]` and expose all markets through `ExecutionContext`:
- `ctx.get_candles(market, lookback)` — peek at other markets for correlation signals
- `ctx.markets` — list of available markets
- Strategies can trade multiple markets simultaneously

**Why #2**: A Solana quant firm's edge is often cross-market (SOL/ETH ratio trades, funding rate arb across perps, spot-perp basis). Single-market-only is a toy limitation. QuantConnect handles multi-asset natively. Even Freqtrade supports multi-pair.

**Effort**: Medium (1-2 sessions)

---

#### 3. Statistical Confidence Layer

**What**: Add to every backtest result:
- Monte Carlo trade-sequence shuffling (1000 iterations)
- Bootstrapped confidence intervals on Sharpe, Sortino, max drawdown
- P-value: "Is this Sharpe statistically different from zero?"
- Probability of ruin estimate
- Display in tearsheet as confidence bands on equity curve

**Why #3**: This is what separates "toy backtester" from "tool I'd allocate capital with." A quant will immediately ask "What's the CI on this Sharpe?" Without this, no professional trusts the output. QuantConnect provides this. Freqtrade does not (competitive advantage opportunity).

**Effort**: Medium (1 session — pure analytics, no engine changes)

---

#### 4. Data Integrity Layer

**What**:
- `FlintStore.audit_candles(market, resolution_s)` — returns gaps, duplicates, anomalies, coverage %
- Warnings embedded in backtest results when data quality < threshold
- Data health dashboard in UI
- Automatic gap detection before backtest with clear warning

**Why #4**: Bad data silently produces bad backtests. A professional discovering this after deploying capital loses trust permanently. This is defensive credibility.

**Effort**: Small (already partially built in `flint/data/quality.py`, needs integration)

---

#### 5. Live Trading Bridge (driftpy Integration)

**What**:
- Add `driftpy` as optional dependency
- Implement `LiveDriftContext(ExecutionContext)` — real orders to Drift
- Keypair loading from env var (`FLINT_PRIVATE_KEY`)
- Position reconciliation (compare local state vs on-chain)
- Error recovery and transaction retry

**Why #5**: The "full lifecycle" promise (research → backtest → optimize → paper → live) is Flint's key differentiator. Currently the lifecycle ends at paper trading — `place_order()` raises `NotImplementedError`. A quant evaluating Flint checks this immediately. Even if they start with backtesting, a dead-end on live makes them choose another platform.

**Effort**: Large (2-3 sessions)

### Tier 2 — Expected by Professionals

#### 6. One-Command Quickstart

**What**: After `git clone && pip install -e .`:
```bash
flint init
```
This single command: creates DuckDB, generates `flint.yaml`, backfills 90 days of SOL-PERP/BTC-PERP/ETH-PERP, runs a sample backtest, prints results. Proves the system works in < 5 minutes.

**Why**: Time-to-first-backtest < 5 minutes is the bar. QuantConnect: click "New Algorithm" → run. Freqtrade: `freqtrade create-userdir && freqtrade download-data && freqtrade backtesting`. Flint needs an equivalent.

---

#### 7. Strategy Scaffolding Wizard

**What**: `flint new strategy` interactive prompt:
- v1 (signal) or v2 (context)?
- What indicators? (MA, RSI, Bollinger, custom)
- Single market or multi?
- Generates `.py` file + test file

**Why**: Reduces "blank page" problem. Jesse has this. Freqtrade has `freqtrade new-strategy`. Professionals want templates that match their intent, not generic boilerplate.

---

#### 8. Terminal-First Results Display

**What**: When running `flint backtest` from CLI, display:
- Rich-formatted metrics table
- ASCII sparkline equity curve
- Trade summary with color-coded PnL
- Warnings if data quality issues found

**Why**: The terminal is where quants live. The UI is for exploration, but CLI output needs to be informative enough to iterate without opening a browser. Freqtrade does this well with formatted tables.

---

#### 9. Backtest Comparison with Statistical Significance

**What**: In UI and CLI, compare two backtest runs:
- Side-by-side metrics
- Paired t-test on per-trade returns: "Is Strategy A's outperformance statistically significant?"
- Overlaid equity curves
- Confidence bar visualization

**Why**: Strategy development is iterative. Without comparison, users screenshot or mentally compare. QuantConnect has this. Freqtrade's FreqUI added comparison features in 2026.

---

#### 10. Hot-Reload Strategy Development

**What**: In Strategy Lab, detect code changes and auto-run a quick backtest on the last 30 days. Sub-second feedback. Full backtest is a separate explicit action.

**Why**: This mirrors QuantConnect's "live coding" experience. Currently every edit requires clicking RUN and waiting. Fast feedback loops are critical for strategy development velocity.

---

### Tier 3 — Differentiators (Solana-Native Advantages)

#### 11. Funding Rate Visualization + Strategy Integration

**What**:
- Funding rate chart in Data Explorer alongside price
- Show cumulative funding cost/income as separate line on equity chart
- Built-in Drift funding rate history (already collected)
- First-class support in strategy API: `ctx.funding_rate(market)`

**Why**: No competitor surfaces funding rates in backtest results. This is Flint's unique Solana/perps differentiator. Funding is often 30-70% of perp strategy PnL.

---

#### 12. MEV Cost Modeling in Backtests

**What**: Add MEV-related costs to fee models:
- Jito tip estimation per trade
- Priority fee modeling
- Front-running cost estimation for large orders
- Display as separate cost line in tearsheet

**Why**: Solana-specific. No other backtester models MEV costs. This makes Flint's backtests more realistic than any competitor for Solana trading.

---

#### 13. Drift v3 Integration

**What**: Update connectors for Drift v3 (launched Dec 2025):
- 10x faster execution
- Gasless trading support
- Improved oracle prices
- New market types

**Why**: Drift is Flint's primary venue. Staying current with v3 is essential for credibility.

---

#### 14. Vectorized Backtest Path

**What**: For simple v1 signal-based strategies with no pending orders, implement a vectorized NumPy path that runs 10-100x faster. Critical for optimization where you run 50-500 trials.

**Why**: QuantConnect is fast (C# core). VectorBT is 1000x faster than event-driven backtesting. A Sharpe optimization with 200 trials on 1 year of hourly data should complete in seconds, not minutes.

---

#### 15. Docker + Docker Compose

**What**:
```bash
docker compose up  # starts API + UI + populates data
```
Official `Dockerfile` and `docker-compose.yml`. No Python/Node installation needed.

**Why**: Freqtrade's Docker support is a major adoption driver. Removes "it works on my machine" issues. Essential for quant firms with standardized dev environments.

## Competitive Positioning Recommendation

**Position Flint as**: "The QuantConnect for Solana DeFi — local-first, free data, backtest-to-live on Drift."

**Key differentiators to emphasize**:
1. Only backtesting platform with native Drift Protocol integration
2. Free unlimited historical data (Drift S3) — no data subscriptions
3. Local-first (DuckDB) — your data, your machine, no cloud dependency
4. Full lifecycle: research → backtest → optimize → paper → live (once driftpy is integrated)
5. MEV-aware backtesting (unique, no competitor has this)

**Segments to target**:
- Solana DeFi traders running perp strategies on Drift
- Small quant firms (1-10 people) focused on Solana
- MEV researchers studying Solana arbitrage/liquidation opportunities

**Segments to avoid (for now)**:
- CEX-only traders (Freqtrade dominates, no point competing)
- Multi-chain DeFi (Hummingbot has broader coverage)
- Institutional multi-asset (QuantConnect owns this)

**12-month competitive risks**:
- Hummingbot adding Drift connector (they added Orca already)
- Drift Protocol building their own backtest tools
- Freqtrade adding Solana/DeFi support via CCXT or Gateway
- Jesse adding DeFi connectors
